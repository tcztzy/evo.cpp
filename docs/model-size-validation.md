# Official model-size exactness record

This record answers a stricter question than “does the model run?”: does the
native runtime execute the registered model's pinned reference contract? Evo 2
uses zero-unequal raw-element gates. ESMC uses the fixed F32 operation contract
and official portable-F32 tolerance gate documented below; those two meanings
must not be conflated.

## Result

Exact support is attached to the complete `model.id`, never inherited from a
size or topology family. The 2026-08-04 audit found the following production
boundary:

also requires zero unequal elements and a generated-byte record.

## Differences found and resolved

### 20B: the missing PyTorch load-time BF16 boundary

The first 20B attempt had the same top-1 token and cosine 0.999982, but it was
wrong: layer 0 was already different and 5,566 final-logit elements were
unequal. The first internal divergence was
`layer_0_mixer_input_projection`.

The 20B checkpoint uniquely stores Hyena projection weights as F32. Vortex's
`load_checkpoint()` first converts model parameters to BF16, copies the F32
checkpoint into them, and only then lets Transformer Engine quantize BF16 to
E4M3. The converter had performed F32-to-E4M3 directly, skipping a real
PyTorch rounding boundary. That changed 2,619,436 of the 201,326,592 layer-0
E4M3 codes.

`TorchE4M3Source.iter_chunks()` now performs F32 → BF16 → F32 → scaled E4M3,
exactly matching the Vortex load path. After reconversion, every 20B prefill
and cached-decode comparison passed raw-bit exact.

### 40B cached decode: `torch.sum` is not a serial loop

The first 40B cached run was exact through the prefill and early decode steps,
then diverged inside layer-1 HCM by two BF16 elements. Projection, short FIR,
pregate, and cache payloads were still exact; the first mismatch was the HCM
FIR output.

Vortex computes `torch.sum(fir_state * h, dim=-1)`. The native kernel had
accumulated 127 products serially. PyTorch reduces the contiguous row into 32
strided lanes and a warp-style `16, 8, 4, 2, 1` tree. Testing every active
history length from 1 through 127 showed that this tree reproduced the
PyTorch raw bits with zero mismatches.

`fir_decode_kernel` and continued FIR execution now use that reduction order,
preserve PyTorch's separate current-product and bias addition boundaries, and
track the dynamically sized Vortex FIR cache rather than treating leading
zero padding as semantic state. The corrected 40B run is exact for all 50
final block outputs, all cached logits, and generated bytes.

## Reproducing the gate

`tools/generate_vortex_vectors.py` creates the independent reference;
`tools/cuda_model_probe.cu` dumps native boundaries; and
`tools/compare_model_vectors.py --require-exact` fails on the first unequal raw
element while reporting its flat index and both payload hashes. See
[the GPU environment record](gpu02-environment.md) for container, driver, and
build details.
