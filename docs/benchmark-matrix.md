# Correctness and benchmark matrix

This matrix separates three questions that are often conflated: does a path
work, is it numerically/scientifically acceptable, and how fast is it? A green
synthetic fixture establishes regression coverage only. A release claim needs
the real official artifact and the environment recorded below.

## Required matrix

| Architecture / path | Evidence class | Correctness or acceptance gate | Performance gate | Current scope |
|---|---|---|---|---|
| StripedHyena2 CUDA `exact` | Synthetic operator/model fixtures | Raw-bit vectors for operators, prefill, cache and generation | None; fixture timing is not published | Every CUDA change |
| `evo2_1b_base`, `evo2_7b`, `evo2_20b`, `evo2_40b` CUDA `exact` | Real checkpoint, pinned Vortex/PyTorch oracle | Zero unequal raw block/logit elements and byte-identical greedy generation | 7B prefill 16/128/1024 and cached decode on idle A800 | Published exact and speed claims |
| `evo2_7b_base`, `evo2_7b_262k`, `evo2_40b_base`, `evo2_40b_bionemo_bf16` CUDA `exact` | No ID-specific raw-bit record | Typed unsupported before weight upload | None | Not a production exact path |
| StripedHyena2 CUDA `fast-q8-kv` | Synthetic paired run against `exact` | cosine ≥ 0.9999, logit MAE ≤ 0.01, top-1/rank/variant-sign agreement = 1 | Report separately; never mix with exact | Experimental profile regression |
| StripedHyena2 CPU `cpu-f32` | Synthetic paired run against CUDA `exact` | cosine ≥ 0.999, logit MAE ≤ 0.1, top-1 ≥ 0.95, rank/variant-sign agreement = 1 | CPU model/context microbench when performance changes | Portable approximate runtime |
| StripedHyena2 CUDA-prefix/CPU-suffix hybrid | Synthetic paired run with fixed `--gpu-layers` | Deterministic placement plus the applicable approximate-profile bounds | Report transfer and end-to-end time separately | Generation and scoring only |
| HyenaDNA CPU `cpu-f32` | Independent synthetic oracle plus real official tiny checkpoint | Synthetic maximum F32 logit error ≤ 2.3841858e-7; real artifact conversion and execution | No upstream-equivalence or speed claim yet | Context ≤ 4096, direct convolution |
| FASTA/FASTQ/gzip/stdin/VCF/reference | Synthetic streaming and malformed fixtures | Record order, coordinates, `O(record/window)` memory contract, complete prior JSONL rows | Throughput/RSS only when changing IO | CPU and CUDA frontends |
| C ABI, server, install and release | Contract fixtures | Ownership, isolation/cancellation, symbol allowlist, consumer link, dependency and metadata checks | Scheduler load test when batching changes | Every supported architecture |

“Real checkpoint” means bytes from a pinned official revision whose size and
SHA256 were verified before conversion. A generated tiny model must be labeled
“synthetic” in reports and cannot promote a backend/profile to supported exact
status.

## Reproduce the maintained gates

Run all portable functional and contract gates:

```sh
cmake -S . -B build -DEVO_CUDA=OFF -DEVO_NPY=OFF \
  -DEVO_WARNINGS_AS_ERRORS=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

For a self-contained runtime measurement, use the built-in command. It shares
the ordinary FASTA/FASTQ/gzip/stdin reader and writes one machine-readable row
per record:

```sh
evo bench -m MODEL --input sequences.fa.gz \
  --warmup 2 --repetitions 10 --ctx 8192 --gpu 0
```

Each row declares schema/command, model path and ID, architecture, artifact and
execution profiles, backend, input path/name/format/FNV-1a identity, context,
warmup, repetitions, tokens, timing scope, every measured duration, median,
and median tokens/s. The hash is a fast run-identity check, not an artifact
authenticity primitive; release claims must still record SHA256 as required
below. Context/model load is reported separately by runtime metrics and is not
included in the `prefill_with_host_logits` benchmark scope.

Run the paired approximate-profile evaluator with the exact and candidate NPY
logits plus biological-score JSON produced by independent executions:

```sh
tools/evo_profile_gate.py \
  --exact-logits exact.npy --candidate-logits candidate.npy \
  --exact-bio exact-bio.json --candidate-bio candidate-bio.json \
  --min-cosine 0.9999 --max-logit-mae 0.01 \
  --min-top1-agreement 1 --min-rank-agreement 1 \
  --min-variant-sign-agreement 1 --report profile-report.json
```

The maintained real 7B A800 gate is `scripts/gpu02_benchmark_7b.sh`. It refuses
a busy GPU, verifies the official checkpoint identity, measures repeated
prefill at 16/128/1024 tokens, compares logits and generated bytes, writes GPU
state before/after, and hashes the whole report directory. The complete
1B/7B/20B/40B exact procedure is recorded in
[model-size validation](model-size-validation.md).

## Performance reporting rules

A benchmark report is reviewable only when it contains:

- source commit and dirty-tree state; binary, artifact/index, input and oracle
  SHA256; architecture, artifact profile, execution profile and backend;
- CPU/GPU model, count and placement, memory, driver, CUDA, compiler, build
  type, build flags, container/image digest, and relevant library revisions;
- command line, input lengths and record count, context, batch/concurrency,
  warmup policy, measured repetitions, synchronization boundary, statistic and
  units;
- model-load time separated from prefill/decode time, plus peak host/device
  memory when memory behavior is part of the claim; and
- raw logs and a machine-readable gate result, including failures and skipped
  cases rather than only the best number.

Use median over repeated steady-state runs for headline throughput and retain
the individual samples. Compare two runtimes on the same idle hardware,
artifact semantics and inputs. Do not compare `exact`, `fast-q8-kv`, CPU, or
hybrid numbers without naming the profile in the table cell.

## Promotion rule

A new architecture, backend, quantization, or execution profile starts as
experimental. Promotion requires a pinned real official checkpoint,
independent reference path, numerical and biological thresholds chosen before
measuring the candidate, all relevant public-surface tests, and a reproducible
environment record. Unsupported cells remain explicit; they are not filled by
fallback to another backend or profile.
